# 基金半年面板复现

本目录是独立的新版本。原工作区代码、数据和目标文件均保留；运行本目录不调用上级目录的旧脚本。目标是严格复现既有数据，不在代码整理时改变研究口径。

## 运行顺序

在本目录、已安装 `requirements.txt` 的 Python 环境中依次运行：

```bash
python build_inputs.py
python rolling_alpha.py
python merge_panel.py
```

也可执行 `sh run_all.sh`。第一步失败应先处理错误，不要跳过后续依赖。重复运行会覆盖本目录的衍生结果，原始数据只读。当前已验证环境位于：

```bash
/opt/homebrew/Caskroom/miniconda/base/envs/fund-manager/bin/python
```

首次安装环境使用 `python -m pip install -r requirements.txt`。依赖版本固定在本次实测版本；六模型的估计可能耗时数分钟，全部评价原表的流式读取可能更久。

| 程序 | 内容 | 下游依赖 |
|---|---|---|
| `build_inputs.py` | 名单展开半年面板；利率按月末向后匹配；接 CSMAR 三/四/五因子和鸣石 CH3/CH4 | `rolling_alpha.py` |
| `rolling_alpha.py` | 六模型独立滚动回归；24 个月历史窗口估计 beta，计算下一月异常收益 | `merge_panel.py` |
| `merge_panel.py` | 规模、持有人、半年买卖、费用、经理、半年收益、六模型 alpha、控制变量、CSMAR 评价合并 | 最终面板 |
| `excel_style.py` | 按字段名设置最终表与 alpha 表的显示格式 | 辅助模块，无需运行 |

代码按 `# %%` 分段，底部 `main()` 显示执行顺序。需要逐段操作时先执行定义区，再按 `main()` 中的顺序运行业务语句。CSMAR 评价读取使用多进程，完整重跑请从终端执行脚本。

## 数据目录

- `原始数据/`：本流程实际用到的 33 个输入文件的完整副本，保留来源子目录，包括 19 个评价批次文件（其中有相同内容副本，程序按哈希去重）。`基金名单.xlsx` 是本流程的既定输入快照，已有名单清洗字段，不声称它是未经加工的供应商原表。
- `中间数据/`：基础面板、月度利率、带因子的月净值、六模型月度 alpha、逐步合并面板、半年末评价切片。全部由以上三步生成。
- `结果/`：最终 `基金名单_fundid_date_TotalEquity_Holder_BuySell_Fee_Manager_Alpha_Controls_Eval.xlsx`。
- `核验/`：原始数据 SHA-256 清单、独立验收程序、核验报告和本次运行日志。这里的迁移辅助代码不属于日常运行流程。

原始和中间数据均已实际复制/生成，无符号链接，也不依赖原目录中已有的 alpha 或 Controls 文件。`.gitignore` 排除原始数据、中间数据、结果和日志；GitHub 仅提交代码、说明和小型核验报告。

## 保留的研究定义

1. 同一 fundid 的名单记录按最早成立日优先、相同则较晚 latest 优先；成立日之后才展开半年末，到期日当天可保留。样本截止 2026-06-30。为复现旧文件，本出口保留 2010 年以前的预样本；正式研究应另行筛选 2010-01-01 至 2026-06-30。
2. 财报以基金主体、代码、报告类别及期末日期匹配。持有人任一总产品比例有值时，整组采用总产品口径，否则采用本份额口径。
3. 买卖及费用的下半年值原则上为同起算日的年报减半年报。有报告行的空值按零；无半年报沿用年报，起算不同留空。相减低于 -0.01 时留空，买卖任一侧减负则两侧都空。全年买卖代替下半年时，Turnover 留空。
4. 团队按任职起止日期匹配，保留董理两期和廖志峰一期的名单空窗补丁。`midAge`、`largeAge` 是证券从业年限中位数和最大值，非生理年龄。
5. 无风险利率采用该月末之前最近一次三个月定存年利率，按 `(1+q/100)^(1/12)-1` 换算。CSMAR 因子采用 P9714、流通市值加权，五因子采用 Portfolios=1；CH 模型使用各自的 SMB 和 CH_rf_mon。
6. 回归窗口为 t-24 至 t-1；当月 alpha 是当月超额收益减历史 beta 乘当月因子，不减历史截距。成立月前数据、建仓月、缺月后首行剔除，窗口不跨缺月。所有回归函数保持旧版实现。
7. `raw_ret` 是半年内六个月的几何平均月收益；各 `*_alpha` 是六个月异常收益的算术平均。六个月不足时留空，均非年化指标。
8. Size=ln(期末净资产)，Age=ln(1+自然月差)；Turnover 和 Expense 分母为相邻半年期初期末平均净资产；Flow 分母为期末净资产。保留旧版极值、负值和缺失，不缩尾。
9. CSMAR 评价选源数据各半年末月份的最大工作日，剔除周末。按当前固定样本复现；若扩展日期，应重新核实交易日历。CLTiming 实际为牛市 beta 减熊市 beta，说明书字段表反向文字不用于改动数据。
10. 保留逐步面板的 Excel 写出再读入，以复现旧链路的数值序列化精度。中间表只简化显示格式；最终表沿用旧版显示格式。

## 时点与异常边界

本次是结果等价重构，不是对识别策略或全部供应商原始数据的重新审计。财报按报告期归属，尚未按公告可得日对齐；经理从业年限为原表快照，三个名单补丁及转型分段仍沿用既有处理。评价日期也不代表数据库实际发布日期。因此不能仅凭重构成功，将最终文件宣称为严格 point-in-time 的预测数据。

既有异常包括全年费用可能代替下半年费用、负费用、极端 Flow/Turnover，以及个别 CSMAR 区间收益与月度净值口径不一致。为保证数据一致，本次不修正它们。日志保留减负、起算不一致和缺失数量。

## 如何验收

在旧版基准文件仍位于本目录上一级时运行：

```bash
python 核验/verify.py
```

该独立程序比较基础面板、利率、全部回归输入、六模型月度 alpha 和最终面板，逐值零容差比较，包含行列顺序和缺失位置；同时核验原始文件 SHA-256，以及 rolling_alpha 全部函数的语法树一致。运行成功生成 `核验/verification.json`。只要求数据一致，不要求 XLSX 压缩包字节或中间表格式相同。验收程序依赖上级旧文件，三步生产流程不依赖它。

## 2026-11-05 实际验收结果

三步已从 `原始数据/` 完整重跑。14 个上游输出和最终面板共 15 个文件通过逐单元格零容差比较；最终 45,929 行 × 84 列的值、缺失位置及行列顺序完全一致。额外核对的 Controls 中间面板 45,929 行 × 40 列也完全一致。

33 个原始文件的新旧 SHA-256 均与清单一致。`rolling_alpha.py` 所有函数语法树与旧版一致，仅改数据目录。原有 12 个 build/merge 文件共 1,977 行，合并后两个文件共 958 行，减少约 52%；滚动回归与格式辅助模块另行保留。

本次上游和最终核验分别执行 `python 核验/verify.py upstream`、`python 核验/verify.py final`，由 `核验/汇总核验.py` 汇总为 `核验/verification.json`。日后默认无参数即可一次验收全部文件。
